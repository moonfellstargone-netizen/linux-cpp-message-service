# 协议说明

## 传输与边界

使用 TCP。一次 `recv` 可能只得到一部分消息，也可能得到多条消息；应用层按下面的长度前缀解析，不能依据接收次数划分消息。

每帧由 4 字节头和正文组成。头为无符号 32 位大端整数，表示**正文的字节数**，不包含头自身；不直接传输 C++ 结构体。

请求正文长度为 1–1024 字节。正文允许任意字节，包括 NUL，不校验编码或 JSON。命令行客户端把用户输入的一行作为正文；行结束符不属于请求正文，空行及超长行在本地提示后跳过，`/quit` 是客户端本地命令。

例如正文 `hi` 的帧为：

```text
00 00 00 02 68 69
└──长度──┘ └正文┘
```

正文长度计算使用字节数，不是字符数。中文在常见 UTF-8 环境下通常由多个字节表示，实际以发送的原始字节为准。

## 请求与响应

服务端对每条合法请求生成一条响应，正文为：

```text
bytes=<请求正文字节数>\n<原始请求正文>
```

上面的 `\n` 表示一个真实换行字节。原始正文逐字节保留；例如 `hi` 对应的响应正文为 `bytes=2`、换行、`hi`。

响应使用同样的 4 字节长度头。客户端允许的响应正文上限为 1056 字节；这是请求上限加 32 字节预留空间。当前响应格式实际所需的额外空间小于这一预留。

服务端支持一条连接上连续发送多个请求，也支持多个请求帧在一次接收中到达。按该连接上解析请求的顺序排队回复。命令行客户端每次发送一条请求并等待一条响应，不主动流水发送。

## 异常与连接生命周期

- 头或正文不完整：保留当前数据，等待后续字节。
- 已收到完整头，但长度为 0 或超过 1024：关闭该连接，不分配声明长度的正文空间，不发送协议错误帧。
- 客户端在残帧中结束发送或断开：不把残帧作为请求处理，记录原因并清理连接。
- 客户端发完完整请求后调用 `shutdown(SHUT_WR)`：服务端识别接收方向 EOF，并先发送已排队的完整回复，再关闭连接。普通断连不保证客户端能收到回复。
- 一条连接的协议或收发错误按该连接处理。其他连接仍应可继续工作；该性质需要由异常隔离测试验证。
- `EAGAIN`/`EWOULDBLOCK` 表示当前操作暂时不能推进，保留状态等待下一次就绪；`EINTR` 需要依据具体操作处理。永久性错误才进入对应的清理路径。

服务端只监听 `127.0.0.1`，不提供账号、身份认证或跨客户端转发。日志中的 `connection` 是进程内递增的排障编号，不是账号或安全身份。

## 资源限制与承诺边界

最多同时保留 64 条连接。每连接接收缓冲上限为 8192 字节，待发送缓冲上限为 65536 字节。达到连接或缓冲限制时拒绝新连接或关闭超限连接；这些策略应结合日志和自动测试核对。

没有应用层消息 ID、持久化、去重、重试或确认机制。收到响应只说明当前请求被该进程处理并返回相应内容；不能据此宣称离线投递、进程故障后的消息恢复或端到端可靠投递。项目尚无连接超时或空闲回收策略。
