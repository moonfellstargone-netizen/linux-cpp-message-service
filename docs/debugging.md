# 真实排障记录

**待记录真实问题。** 当前没有可宣称已经定位、修复并回归验证的案例。预设故障、猜测原因或正常的错误提示，都不能包装成已解决的项目问题。

出现可复现问题后，按以下顺序记录：

1. 现象：实际输出、触发时间、源码版本、系统与构建方式，以及期望行为。
2. 最小复现：启动命令、输入内容、连接数量及操作顺序，说明能否稳定复现。
3. 证据：相关日志、错误返回、测试失败信息；需要时再补调试或抓包结果。
4. 假设与核对：区分已观察事实和推测，说明哪条证据支持或排除了哪个原因。
5. 修正：实际修改的位置和原因，避免只写“优化逻辑”。
6. 回归：同样条件下复测原问题，并运行相关正常、边界及异常用例，记录剩余限制。

首个真实案例由实际验证后补充。本文件不是已完成排障能力的证明。
