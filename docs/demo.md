# 演示与故障复现

Linux 手工演示状态：**待执行**。先按 [README](../README.md) 完成构建，使用现有 Ubuntu 中的三个终端即可，不需要多台机器或复杂网络环境。

## 三终端正常演示

终端 A 启动服务端：

```bash
./build/message_server 9000
```

终端 B 启动第一个客户端：

```bash
./build/message_client 127.0.0.1 9000
```

输入 `hello`，应收到包含 `bytes=5` 和原始 `hello` 的响应。这里描述的是预期结果，实际展示以执行输出为准。

终端 C 启动第二个客户端，输入不同内容：

```bash
./build/message_client 127.0.0.1 9000
```

回到终端 B 再输入一条消息，确认两个客户端各自得到服务端回复。B 的消息不会转发给 C。输入 `/quit` 退出其中一个客户端，另一个应仍可继续请求。

## 故障复现与观察

1. **客户端异常退出。** 保留终端 B 的连接，在终端 C 的客户端按 `Ctrl+C`。观察服务端是否清理 C，并再次从 B 请求。重新启动 C，检查能否继续连接。这不证明所有断连情况均已覆盖。
2. **连接目标没有服务。** 停止服务端，再启动客户端连接相同端口，观察连接错误与退出状态。重新启动服务端后应由用户重新运行客户端；没有自动重连。
3. **端口占用。** 已有服务端监听 `9000` 时，在另一个终端再启动同端口服务端，观察启动失败信息。可改为 `9001` 后使用匹配端口的客户端验证。
4. **残帧与非法长度。** 使用自动集成测试分别发送半个头、半个正文及非法长度，同时检查正常连接仍可用。CLI 每行生成合法帧，不适合手工模拟这些输入。

先写下预期，再记录实际输出及服务端日志。如果结果不同，保留最小触发步骤，按照 [排障记录流程](debugging.md) 定位。故障复现步骤不能直接作为“已经发现并修复的案例”。
